# Публикация портфолио

Одобренный вариант опубликован: https://onewaez.github.io/waez-portfolio-v2/.

Исходники: https://github.com/onewaez/waez-portfolio-v2. Для последующих изменений сначала проверяется предпросмотр на http://127.0.0.1:4322/, затем вручную запускается публикация. Старая версия сохранена отдельно и доступна на порту 4321.

## GitHub Pages

Сайт размещён в отдельном репозитории `onewaez/waez-portfolio-v2`.

В **Settings → Pages → Build and deployment → Source** уже выбран **GitHub Actions**. Workflow из `.github/workflows/deploy.yml` запускается только вручную через **Actions → Deploy portfolio to GitHub Pages → Run workflow**. Обычный push не публикует сайт.

Workflow устанавливает зависимости, проверяет проект и собирает сайт с `BASE_PATH=/waez-portfolio-v2/`. Ссылки, шрифты, favicon, canonical и sitemap учитывают этот префикс.

Состояние публикации видно на вкладке **Actions**. Если проверка или сборка завершится ошибкой, новая версия не публикуется: исправьте ошибку из лога, отправьте следующий commit и повторно запустите workflow.

## Любой статический хостинг

На компьютере с Node.js 24:

```sh
npm ci
npm run build
```

Загрузите **содержимое** папки `dist/` в корневую папку сайта на хостинге. `index.html` должен находиться в корне, рядом с `_astro/`, изображениями и остальными файлами. На сервере Node.js не нужен.

Для получения ZIP-архива (нужен Python 3):

```sh
npm run package
```

Готовый архив: `artifacts/waez-portfolio.zip`. Он содержит готовый сайт, без исходников и `node_modules`. Хостинг должен поддерживать раздачу обычных HTML/CSS/JS-файлов и HTTPS. Специальные перенаправления для SPA не нужны.

Для быстрой проверки переноса:

```sh
python3 -m http.server 8080 --directory dist --bind 127.0.0.1
```

Откройте http://127.0.0.1:8080/. Локальный сервер нужен только для проверки. Опубликованный сайт работает независимо от вашего компьютера.

## Другой домен

Если меняете домен, обновите `site` в `astro.config.mjs`. Для размещения в подпапке передайте `BASE_PATH=/имя-папки/` при сборке. Canonical, Open Graph, robots.txt и sitemap.xml создаются автоматически. Сборка без `BASE_PATH` предназначена для корня домена.

### Подключение is-a.dev после получения домена

Следуйте [официальному руководству is-a.dev для GitHub Pages](https://docs.is-a.dev/guides/github-pages/). В заявке используйте публичную ссылку на сайт и его скриншот. DNS-запись CNAME должна указывать на `onewaez.github.io`, без `/waez-portfolio-v2/`.

После принятия заявки добавьте выданный домен в **Settings → Pages → Custom domain**. Для нового адреса нужно обновить `site`, установить `BASE_PATH: /` в workflow и заново собрать сайт. После выпуска сертификата проверьте **Enforce HTTPS**. До получения домена текущая конфигурация остаётся рассчитанной на GitHub Pages в подпапке.

## Новый проект

Добавьте Markdown-файл в `src/content/projects/`, задайте следующий уникальный `order` и добавьте изображения в `public/projects/`. После проверки и одобрения запустите ручную публикацию. Порядок: старые проекты → новый проект → About → Contact. Формат описан в README.md.
